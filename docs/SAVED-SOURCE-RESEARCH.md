# Saved-source research without workspace bookkeeping

A request that reads an existing artifact and reports or publishes its contents can finish from that evidence directly. Successful read_artifact evidence is required before this exemption applies. A bound workspace, a completed progress list and a coordination post alone do not make it a file-editing task. Existing tool availability, authorization and factual checks stay in place.

The exemption is deliberately narrow: a requested local deliverable, an explicit implementation/save/download/export action, a recorded workspace mutation, or an observed workspace read/write or code execution keeps the existing completion path. Requests that fail to read their artifact also keep it. Other research forms retain their existing behavior. The normal harness wording makes a progress list optional for reading saved results and answering or publishing their contents.

A published-content introduction such as "Incluido en el post:" or "Added in the message:" does not assert that the source path subsequently quoted was edited. A later actual edit claim remains checked, as does an inclusion written into a file such as post.md. The deliverable parser now uses word boundaries around action verbs and excludes Spanish past participles plus created/generated, so a saved/generated source is not mistaken for a request to produce its path. Other input/output-role ambiguities are outside this change.

Silver1763 follows native1760, where four redundant source reads and mandatory bookkeeping accompanied a correct three-ordinal result; the completion audit then produced a false source-file modification warning. The original fourteen-case contract failed five cases before this change and now passes all fourteen. A separate six-case parser contract, frozen before that file changed, failed four cases and now passes six. Regressions pass320 tests, including a simulated loop with four successful source reads that ends without mandatory progress or completion audit and preserves genuine workspace cases. Fixtures carry a valid run-artifact identity; invalid synthetic identity and a constant fake output initially stopped at the existing authority gate. Those observer failures are retained, separately from the real parser bug. The initial colon-consuming reference pattern also failed three cases and was corrected to a lookahead. Native model efficiency and UI behavior still require a subsequent real run; these fixtures establish neither factual correctness nor a global speedup.
