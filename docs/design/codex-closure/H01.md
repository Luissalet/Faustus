# H01 - Code Mode is a capability runtime, or an explicit host execution

Acceptance: there is no filesystem or network access outside the declared contract.

Status: CLOSED-WITH-LIMIT (limit: the confined runtime needs a reachable container backend; without one Code Mode refuses instead of falling back to the host).

## Already there
- Bridge-only tool policy (`tools.call` goes through the normal approvals and disabled-tool checks), receipts per nested call (`src/code_mode/outcomes.py`), cancellation and Windows Job Object cleanup for the host process.
- `runtime_guarantees` on host results saying that the filesystem and the network were NOT isolated.

## Added
- `src/code_mode/confined.py`: the confined plan. `docker run -i --pull never --user <uid:gid> --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp:rw,noexec,nosuid --pids-limit --memory/--memory-swap --cpus --ulimit cpu --network none|bridge -w /workspace`, only the declared workspace roots bind-mounted (read-only by default, read-write by grant, nothing with `workspace_access=none`), no Faustus environment variable and no secret, no Faustus file mounted (the guest source and the user code travel over stdin; `guest.py --inline`). Explicit `docker kill` and `rm --force` in a `finally`, OOM detection reports `terminated_by: memory`.
- `src/container_mounts.py`: `--mount type=bind,...` spelling (never `-v`, so drive letters are not split), Windows paths to a Linux container path, refusal of UNC paths and of paths with commas or quotes.
- `src/code_mode/runner.py`: `run_code_mode(runtime=confined|host)`. The default is `confined` (setting `agent_code_mode_runtime`). `host` is an explicit opt-in. When confinement is required but unavailable (daemon down, image missing, unmountable path) the result is a refusal (`refused: true`, exit 126, `mode: not_executed`); there is no host fallback. `host` is refused when `agent_sandbox_mode` is `required`. Every result carries `runtime_policy {requested, effective, reason}` and the effective `runtime_guarantees` (`mode: container`, `filesystem_scope`, `network_isolated`, `host_environment_passed: false`, `secrets_passed: false`, limits). Host guarantees are unchanged.
- Stray output on the protocol channel is bounded (`terminated_by: output`); non-object frames are ignored.
- Settings (Agent settings, Code Mode group): `agent_code_mode_runtime`, `_workspace_access`, `_network`, `_memory_mb`, `_max_processes`.
- Tool text (`run_code` in `tool_schemas.py` and `tool_index.py`) describes both runtimes honestly.

## Tests
`tests/test_code_mode_confined.py` (30): plan arguments (no env passthrough, no network by default, grants, sibling roots, Windows path spelling, unmountable paths refused), refusal without spawning anything, default runtime is confined, host refused under `required`, and against a real container: decoy outside the root, sibling directory, symlink inside the root, read-only by default and writable on grant, no files without a grant, no Faustus environment or host files, network blocked unless granted, child process confined too, descendants die with the container on timeout, stdout spam bounded, memory limit, bridge write with approval and denial, cancellation during approval removes the container. The pre-existing Code Mode suites run under the explicit `host` runtime fixture (`code_mode_host_runtime`) and still pass.
Container tests skip when there is no daemon or no image with python3 (`FAUSTUS_TEST_CONTAINER_IMAGE` overrides the image).

## Limits
- Needs a container backend and an image with `python3` (`faustus-sandbox:1`, `scripts/build_sandbox_image.ps1`). Without one Code Mode refuses.
- A confined run with a read-write workspace or with network can still have effects outside the bridge; H16 reports those as `uncertain`.

## Windows verification (01-10-2026)

On Windows 11 with Docker Desktop 28.5 and the `faustus-sandbox:1` image, `tests/test_code_mode_confined.py` and `tests/test_sandbox_probe.py` pass against real containers, and the probe run from the dev instance reports `verified` for `shell`, `python`, `code_mode`, `files` and `descendants` (drive-letter mounts, `host.docker.internal` network check, directory junction fixture).
