# H09: stable prefix and context receipts by version

## Acceptance criterion

Hashes and sources make a change in context explainable: what the compiler built,
what the loop added after it, what reached the route, and why one round differs
from the previous one.

## Already there

- The compiler manifest described the packet it built (`src/context_engine`), but
  the agent loop then adds blocks of its own (harness note, reply-language
  directive, skills index, repository map, compaction summary), trims for the
  route, and the transport may rewrite the list once more. The manifest could not
  say what the model actually read.

## Added (commit `3da73b57`)

`src/context_engine/prompt_audit.py`: pure functions over data the loop already
holds, plus one recorder that never raises into a turn.

- `fingerprint_prompt`: one hash per block of the exact list about to be sent and
  cumulative prefix hashes. Only wire fields take part (role, content, name, tool
  call fields), so private loop markers and metadata never make two identical
  prompts look different. Tool schemas are part of the identity.
- `source_receipts`: one row per compiled item with its reference, version state
  (`declared`, `content_hash`, `unversioned`) and content hash. A source without a
  declared version says so and still carries its hash.
- `query_receipts`: memory, document, objective and file queries as identities
  and hashes, never the query text or a path.
- `reconcile`: the manifest against the final prompt: packet present and intact
  (byte for byte), which compiled sources are still in it, blocks added after the
  compiler (grouped by origin) and compiled sources lost after delivery.
- `diff_prompts`: two consecutive rounds: common prefix, the first divergence with
  the bucket that caused it, added, removed and changed blocks, and a separate flag
  for a tools change. A prefix break is counted per turn.
- The wire body handed to the transport is compared with the loop's view; a payload
  without messages is reported as not comparable, not as equal.
- A hash of the context-shaping settings (`CONFIG_KEYS`), with unreadable settings
  recorded as unreadable, never as their default.
- Skill and instruction provenance carried on messages reach the round record
  (`skill_receipts`, `instruction_receipts`); the producers for those are H21.
- Persisted hash-only with the turn; read by `GET
  /api/context/sessions/{id}/prompt-audit`, the MCP tool `context_prompt_audit`
  and shown next to the context receipts in the transcript (version or
  "unversioned", first hash digits).

## Limits

- The audit is an observation: it says what was sent and what changed, it does not
  reorder the prompt. The stable-prefix property is measured (prefix break counted
  with its cause), not enforced.
- Hashes identify text; they do not prove the provider used it. The wire comparison
  covers the body the transport reports, not what the server did with it.
- A source that declares no version carries only its content hash.
