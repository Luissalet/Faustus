# H24 - Compare real success and boundaries, not only final text

## Acceptance criterion

A paired harness bench: same model, version and effort, same task, before vs after (a git
revision or a settings toggle). Tasks have checkable outcomes (files, tests, effects).
Recovery scenarios: kill mid-tool, restart, approval after restart. The report gives
success, rounds, seconds, tokens and boundary violations. Each bench case runs with its own
data dir and workspace and no global state leaks (a fixture fails on leaks). A script and
docs give the exact Windows command against the local 27B at `http://127.0.0.1:8081/v1`.

## What was already there

* `tests/eval/` ran six representative tasks through a real server process with a
  scripted model, against one shared server and a baseline file. There was no second arm,
  no boundary check, no recovery scenario, no isolation guard and no way to point it at a
  real model.
* `src/bench/runner.py` and `scripts/benchmark_*.py` are other benches (context, research);
  none compares two arms of the agent harness.

## What was added

* `src/bench/harness_pair.py` (new, no server, no model): `RunRecord`, `Sandbox`
  (workspace, canary directory beside it, data dir; one throwaway root per run),
  `check_boundaries` (canary changed, workspace file changed outside the case's allowed
  globs, forbidden tool used, duplicate effect), `capture_process_state` and
  `state_leaks` (working directory, watched environment variables, stand-in modules in
  `sys.modules`, files in watched directories), `stale_state_in`, `summarize`,
  `compare` (verdicts `regression`, `blocked`, `inconclusive`, `faster`, `slower`,
  `equivalent`; a success drop or a new violation is decided before speed; fewer than
  `min_repeats` runs gives `inconclusive` with no invented percentage; a pair whose models
  differ is labelled whole-system), `build_report`, `render_text`, `list_reports`.
* `tests/eval/harness.py::EvalApp`, additively: `repo` (run a second revision),
  `settings` (written to the run's own data dir), `endpoint` and `model` (a real
  OpenAI-compatible model; `script()` becomes a no-op), `isolated_fake` (the scripted
  model as its own process), `data_dir`, `kill`, `restart`, `stop(cleanup=)`, and
  `send_turn(reasoning_effort=)`.
* `tests/eval/paired_cases.py`: the six tasks with the files each may change, and two
  recovery scenarios, `recovery_kill_mid_tool` and `recovery_approval_after_restart`
  (see `docs/design/paired-harness-bench.md`). `run_case` makes a fresh sandbox and a fresh
  server per run and checks the sandbox is gone afterwards.
* `scripts/harness_paired_bench.py`: arms `current`, `rev:<git revision>` (detached
  worktree, removed afterwards) and `set:key=value`; `--endpoint`, `--model`, `--effort`,
  `--repeats`, `--cases`, `--plan`, `--out`; baseline and candidate runs are interleaved so
  drift hits both; exit status follows the verdict. Reports go to
  `<data dir>/benchmarks/harness_pair/`.
* `tests/eval/isolation.py` and the hook wrappers in `tests/eval/conftest.py`: every test
  under `tests/eval` fails if it leaves global state different from how it found it. A hook
  wrapper rather than a fixture, so it runs after every fixture and monkeypatch has been
  torn down.
* MCP: the `harness` built-in server tool `paired_bench_reports` lists and reads reports.
* Docs: `docs/design/paired-harness-bench.md` (arms, cases, isolation, the exact Windows
  commands, how to read a verdict).

## Evidence

* The script was run end to end with the scripted model: `rev:HEAD` against
  `set:llm_projection_mode=legacy` on two cases gave 4 of 4 runs successful, no violations,
  and the verdict `equivalent` (median seconds -0.2%, inside the band).
* Recovery, scripted model, real server: a command running under a SIGKILLed server ran
  once, did not run again after the restart, and the run log was marked `interrupted`; an
  approval card answered after a restart ran the command exactly once.
* The MCP server was exercised through a real stdio client.

## Remaining limits

* Not yet run against the real 27B: this environment has no local model. The scripted
  model measures the harness and its boundaries, not model quality. The Windows command
  is in `docs/design/paired-harness-bench.md`.
* With a real model the runs are noisy; the verdict needs `--repeats` of at least 3 and is
  `inconclusive` below that.
* The revision arm needs that revision to boot with the installed packages and any
  untracked assets it needs.
* `set:` values are scalars.
* A boundary violation by a shell command is seen only through what it changed on disk
  (workspace and canary); it is not attributed to a tool.
