# H17 - direct / deferred / code-only exposure by descriptor

## Acceptance criterion
Exposure (direct, deferred, code-only) is a descriptor field used by
discovery and schema emission; candidates beyond the 256-row window are
reachable through lookup; legacy adapters are covered; a measurement on the
existing tool-index benchmark shows fewer tokens without lower selection
accuracy.

## What already existed
`src/tool_serve.py` (`partition_offer`, compact catalogue, `lookup_tools`,
`search_catalog` with `candidate_filter`), the hot seed in `agent_loop`
(everything retrieval selected got a native schema unless a domain floor
deferred it), the 256-row permission-aware window in `ToolIndex.retrieve`,
the benchmark `tests/test_l91_natural_language_tools.py`.

## What was added
- `Exposure` and `RegisteredTool.exposure` (H05); `DEFERRED_FAMILIES` in
  `src/tool_authority_catalog.py` gives 73 heavy, narrow tools (code graph,
  swarms, fan-out, boards, goals, requirements, autonomy tools, WhatsApp...)
  the DEFERRED default; the other 152 are DIRECT.
- `src/tool_exposure.py`: `demote` (a DEFERRED tool that retrieval alone
  picked and the request gives no lexical evidence for is listed in the
  catalogue instead of carrying its schema), `has_evidence` / `trigger_stems`
  (name parts plus rare words of the tool's own examples, five-letter stems),
  `code_only_names`.
- `src/agent_loop.py`: both retrieval paths record their pool; before the
  offer is partitioned, demotion runs under `agent_tool_exposure`; CODE_ONLY
  tools leave the offer (no schema, no catalogue line). Forced and
  caller-pinned tools are never demoted; sticky toolsets keep the previous
  hot set.
- `src/step_snapshot.py`: a model step's call to a CODE_ONLY tool is refused
  (`code_only`); a bridge call carries no snapshot.
- `src/tool_serve.py`: `search_catalog` never proposes a CODE_ONLY tool; when
  a permission filter leaves fewer than `k` candidates the permitted pool is
  completed by the lexical lane, which scans the whole corpus under the filter
  (reaches past the vector lane's 256 rows). A legacy adapter (an index whose
  `retrieve` has no `candidate_filter`) keeps its explicit cutoff - it is still
  asked for exactly `k`, as `tests/test_lookup_permission_before_limit.py` and
  `tests/test_tool_index_permission_cutoff.py` require - and is completed from the
  permitted pool when it exposes `lexical_retrieve`.
- Setting `agent_tool_exposure` (default on).

## Evidence (benchmark, lexical lane, top 8 per query, 121 cases)
Schema tokens sent natively: 314,597 -> 249,975 (-20.5%). The expected tool
keeps its native schema in 120 of 120 retrievable cases (same as before);
every retrieved tool stays native or in the catalogue (reachability
unchanged). The threshold was chosen on the benchmark: a word counted as
evidence only if at most 3 tools' examples use it; 2 lost accuracy (119/120),
3 and 4 kept it (120/120), 3 saves the most.

## Remaining limits
- The measurement uses the lexical lane (the embedding lane cannot be run in
  this environment); the real saving depends on how many deferred tools the
  embedding lane retrieves on a real request.
- Evidence is lexical. A request that only paraphrases a deferred tool
  without any of its words gets the tool in the catalogue and the model calls
  it through `lookup_tools` or a fenced block - one extra step, never a lost
  tool.
- Tools added to the hot seed by a domain rule and also retrieved are treated
  as retrieved (demotable) unless the request speaks of them.
- No real `CODE_ONLY` tool is registered yet; the path is proven with a test
  registry, and the Code Mode bridge itself is owned by other work.
