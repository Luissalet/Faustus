# H02 - Verifiable environment and confinement contract (Windows)

Acceptance: host, container and native sandbox are never confused.

Status: CLOSED-WITH-LIMIT (limit: there is no native Windows sandbox; confinement on Windows is the Docker Desktop container route).

## Already there
`sandbox_exec` (strict/required modes, refusal text), `sandbox_provider` (persistent sessions), `execution_backends.DockerWorkspaceBackend`, the Windows Job Object helper and the execution-environment block of the system prompt.

## Added
- `src/sandbox_probe.py`: `run_sandbox_probe(operations, image)` tries REAL allowed and forbidden accesses per operation through the configured backend. Operations: `shell`, `python`, `code_mode`, `files`, `descendants`. The fixture holds a root, a sibling directory that shares the root's name prefix, an outside decoy, absolute and relative file symlinks, a directory link (junction through `mklink /J` on Windows), an environment marker and a local HTTP server. 13 checks per container operation (read inside, write inside, outside absolute path, outside relative path, sibling absolute and relative, symlink and directory link do not extend access, host environment not inherited, network to the local server, child process reading outside, child process network). Each check reports expected, observed, ok and evidence; markers are never echoed. A denial with no recognisable reason is `ok: null` (inconclusive), never a pass. Status is `verified`, `verified_with_gaps`, `failed`, `unavailable` (backend unreachable: never verified) or `verified_but_not_in_effect`. The report also says which route real calls take and whether the backend is actually in effect.
- Surfaces: function `run_sandbox_probe`, builtin tool and MCP tool `sandbox_probe`, `POST /api/sandbox/probe`, `GET /api/sandbox` (policy plus per-operation coverage). `mcp_servers/execution_server.py` (native twin registered in `builtin_mcp.py`).
- Windows coverage is stated per operation (`COVERAGE`, rendered in the report for the host in use).
- Required mode on Windows now routes `bash` and `python` to a Linux container (Docker Desktop) with Windows paths mounted through `container_mounts`; it refuses, without falling back to the host, when the daemon or image is missing, for PowerShell and for managed processes. Code Mode under `required` refuses the host runtime (`tests/test_code_mode_confined.py::test_host_runtime_is_refused_when_required_confinement_is_on`).
- `doctor`, the execution-environment prompt block and the settings help describe the route actually in effect.
- `DockerWorkspaceBackend` and `sandbox_provider` mount through `--mount` (Windows paths work, unmountable paths are refused at preflight).

## Tests
`tests/test_sandbox_probe.py` (16): fixture (sibling, links, env marker, cleanup), judging (hole, pass, inconclusive), expectations follow the grant, coverage per operation, file policy probe on the real policy and on a policy that allows everything (reported failed), unreachable backend is `unavailable`, unknown operation reported, routes and tool, MCP server, and with real containers: full verification, a widened mount is detected, an open network is detected, no containers or temp files left behind. `tests/test_sandbox_required_mode.py`: required Windows refusal without a container, PowerShell refusal, bash through the container with Windows workspace paths, prompt and doctor text.

## Limits
- No native Windows sandbox exists; on Windows the only confinement is the Linux container (Docker Desktop, WSL2) and the Job Object that contains host processes. The probe says so per operation.
- The `mklink /J` junction check and the Docker Desktop `host.docker.internal` network check run only on Windows.

## Windows verification (01-10-2026)

The probe ran on Windows against Docker Desktop: every operation `verified`. The widened-mount test uses the Windows form of the attack (a host folder mounted next to `/workspace`), because a Windows host path is never a path inside the Linux container; it is reported `failed` with the relative outside and sibling reads as the failing checks.
