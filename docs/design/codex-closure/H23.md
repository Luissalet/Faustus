# H23 — a user can explain where a turn's cost went

**Status: closed with limits.**

## Acceptance criterion

A per-turn cost and latency view grouped causally by phase (main rounds, tools,
compaction, recovery, advisor, workers and children, retries), where an unknown cost
stays unknown. A backend route, a Studio panel in the turn's metrics UI, an MCP or
built-in read tool, es/en strings.

## What was already there

`metrics.execution` (INF-03): a per-phase timeline of one reply (queue wait, load,
prefill, generation, tools) and `llm_trace` rows per model call. Neither grouped the
turn by cause, nor saw compaction, advisor, recovery or workers.

## What was added

- `src/turn_cost.py`: groups the run's ledger rows (`model_call`, `attempt_result`,
  `child_result`) into `main_rounds`, `tools`, `compaction`, `recovery`, `advisor`,
  `workers`, `retries`, `other_model`. A total is the sum of the calls that reported
  it; `*_unknown_calls` counts the rest; nothing reported is `null`; estimated token
  counts are separate (`estimated_calls`); `unaccounted_ms` is the wall clock minus
  known phase time.
- Model calls reach the ledger from `src/llm_trace.py` (phase, transport, model,
  usage, duration), `src/llm_core.py` (its two record sites), `src/advisor.py` and
  `src/agent_tools/subagent_tools.py` (worker results), under the run that made them.
- `GET /api/runs/{session_id}/turn-cost`; built-in tool and MCP tool
  `run_report view=cost`; rendering in `src/run_report_render.py`.
- Studio: `components/TurnCostBreakdown.tsx` ("Where did the cost go?") under each
  finished reply that has a run id, next to the existing timeline; it loads only when
  opened and shows "unknown" for nulls and "at least" for partial sums. The run id
  comes from `metrics.runId` (live `metrics` event `trace_id`, saved reply
  `metadata.run_id`). Strings in `docs/ui/i18n/es.tsv` and `studio/src/i18n/es.ts`.

## Evidence

Browser checklist (Windows PC): run a turn that uses a tool and, if configured, the
advisor; under the reply open "Where did the cost go?"; each phase shows calls, time,
tokens in/out and cost, unknown values read "unknown", not 0; a tool step with an
unknown effect is flagged; reload the page and open it again on the same reply.

## Remaining limits

- Retries inside one model call (the transport retrying before it answers) are part
  of that call's duration and are not itemized.
- Cost in money is shown only for calls whose usage record marks it `known`; calls
  without one (local models, for instance) read "unknown".
- Turns from before this change have no ledger rows: the panel says no record was kept.
