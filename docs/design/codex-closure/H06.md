# H06 - a snapshot per agent step

## Acceptance criterion
Each agent step captures the announced catalogue version, the owner context,
the environment and the policy; every call references its step's snapshot; a
security revocation wins over an older grant; an MCP update does not
retroactively change the contract of a call already in flight. Shadow receipts,
PDF and MCP bindings are generalised through the registry.

## What already existed
`src/tool_schema_receipts.py` (hashes of announced definitions, used as shadow
receipts), `src/tool_security.py` (`blocked_tools_for_owner`, tool policy), the
workspace grant store and the `bypass` flags in the
loop's security context, which were computed once per turn.

## What was added
- `src/step_snapshot.py` (pure): `StepSnapshot` / `AnnouncedTool` (names,
  canonical ids, semantic and full schema hashes, exposure, catalogue version,
  owner reference that carries no identity, environment, policy denials at
  capture), `capture_step`, `authorize_call` (order: mode off / no snapshot;
  another session or owner ignores the snapshot; LIVE revocation over anything
  captured, under every spelling; CODE_ONLY refusal; unannounced tools follow
  `agent_step_snapshot_unannounced`; MCP drift by semantic hash, descriptions
  ignored, the announced contract applies), `live_mcp_definition`,
  `snapshot_for_answer` (never substitutes another round or candidate).
- `src/tool_execution.py`: `execute_tool_block(..., step_snapshot=...)`
  judges the call, refuses a revoked call before any effect and attaches the
  receipt (`step_snapshot`) to the result.
- `src/tool_capabilities.py`: `workspace_grant_bypass` / `revalidate_workspace_grant`
  - the workspace-grant bypass is revalidated at every `decision_for`, so a grant
  revoked mid-run withdraws it; an unreadable store withdraws it.
- `src/agent_loop.py`: a snapshot is captured when the provider request is
  prepared (`candidate_request_factory`) and passed to each call of that step.
- Settings: `agent_step_snapshot_mode` (off | shadow | enforce, default
  enforce), `agent_step_snapshot_unannounced` (allow | shadow | refuse, default
  shadow), both in `DEFAULT_SETTINGS` and `src/agent_settings_schema.py`.

## Evidence
A call made after its tool was disabled is refused with status `revoked` and an
observation naming the step; an MCP tool whose schema changes between step and
execution is reported (`contract_changed`) and refused under enforce.

## Remaining limits
- A `StepSnapshot` records the announced contract and the live checks run at
  execution; it does not pin the handler code itself.
- Only MCP definitions are re-read live; for core tools the registry is
  process-static, so there is no drift to detect.
- `unannounced` defaults to `shadow` (reported, allowed) because some paths
  execute tools the model reached through a fenced block the step did not
  announce as a native schema; `refuse` is available as a setting.
