# H16 - Common verification for direct calls, Code Mode and workers

Acceptance: the end of a handler does not automatically mean Verified.

Status: CLOSED.

## Already there
Five separate judgements: `TurnLedger.check_completion` (words against the tool log), `completion_gate` (tests and smoke), the changeset proof (`prove`: proved / partial / unproved / contradicted), worker evidence (`claimed_only`, `unguarded`, exit code) and Code Mode per-call receipts (`CallOutcomes`). None could see the others.

## Added
`src/outcome_verification.py`: `verify_outcome(evidence)` classifies work as `verified`, `unverified` or `uncertain`. Precedence is unverified, then uncertain, then verified; verified needs at least one positive observation, and no evidence at all is `unverified` (`no_evidence`). It recomputes nothing: it reads tool results (exit code, `ok`, `result_status`, approval and block flags), test runs, UI smoke, the completion check, the changeset verdict, process handle states, Code Mode results and worker results. Every decisive row names its kind and source. It never raises. Setting `agent_outcome_verification` (default on) controls only whether results carry the block.

Rules that matter:
- Exit code other than 0, a failing test run (new failures), a failed smoke check, a contradicted or unproved changeset with claims, a claim the log does not support, a blocked or approval-held call, a worker whose `claimed_only` files the checkpoint did not see: `unverified`. A failure cancelled by a later success of the same tool is a note; a failed lookup is a note.
- Cancelled, timed out, `outcome_unknown` or partial results, inconclusive or pre-existing-only test failures, `lost` / `orphaned` / `uncertain` processes, an external agent that ran outside the command guard, a partly proved changeset: `uncertain`.
- Code Mode: only bridged calls are receipted, so code that ran directly on the host is ALWAYS `uncertain` about its own effects, even with a proved diff and clean nested receipts. A confined run with read-only workspace and no network can be `verified`; with a read-write workspace it is `uncertain` unless a change diff the checkpoint saw covers it; with network it is `uncertain`. A refusal is `unverified`; a timeout or OOM is `uncertain`.

Wiring:
- `TurnLedger.record` keeps the small evidence (`code_mode`, `process`, exit code, status) and `TurnLedger.verify_outcome()` classifies the turn; `check_completion` returns `verification` beside its own `ok` and `reasons`; the agent loop adds it to the `harness_check` (verified) event and to `harness_summary` (`verification`).
- `completion_gate` now asks the same function (tests, smoke, changeset); its gating behaviour is unchanged.
- `run_code_mode` attaches `outcome_verification` to every result, including refusals.
- `dispatch.compact` attaches it to a finished job (diff, `claimed_only`, verification, proof and each worker row); `external_worker.run_task` attaches it to its own result.

## Tests
`tests/test_outcome_verification.py` (49): every section, precedence, recovery and lookup notes, all process states, host-direct effects always uncertain (also with a proved diff), confined read-only verified in a real container and read-write uncertain, refusal, timeout and nested receipts, worker cases (failed, timeout, cancelled, unguarded, gated, claims not on disk, unguarded proof), dispatch compact (verified, failing verification, ghost claim, running job has none, setting off), ledger integration, `check_completion` carrying the classification, the gate backed by the same function, malformed evidence never raises. Existing `test_completion_gate`, `test_p1_plan06_completion_gate`, harness, changeset, prove, dispatch, external worker and Code Mode suites pass.

## Limits
- The classification is reported and is the basis of the completion gate's existing reasons; it does not add new gating reasons (a failed tool call alone does not downgrade a turn), to keep today's flow.
- The Studio UI does not render the new block yet; it travels in the `harness_check` and `harness_summary` events and in tool and job results.
