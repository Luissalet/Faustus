# H07 - extract decisions from the agent loop

## Acceptance criterion
Pure decision functions / turn context are extracted from `agent_loop`
incrementally; characterization tests with scripted model responses cover a
nonexistent tool correction, a text-only answer, the context limit, permission
denied, failing tests, a partial result and cancellation, asserting the action
sequence and the terminal state. At least the continuation / closing decisions
are extracted.

## What already existed
Shadow decisions in `src/continuation_decision.py`, `src/loop_breaker.py` and
the completion engine; no scripted-model characterization of the generator.

## What was added
- `src/loop_decisions.py` (pure): `TextRoundState`, `decide_text_round`
  returning one of `continue_length`, `correct_unknown_tool`, `nudge_empty`,
  `ask_empty_exhausted`, `correct_language`, `check_claims`, with the
  permission to spend an extra round injected as `permits`.
- `src/agent_loop.py`: the closing stage of a text-only round asks
  `decide_text_round` and applies the action it returns (effects - messages,
  events, counters - stay in the loop).
- `tests/test_agent_loop_characterization.py`: the real `stream_agent_loop`
  body with only the provider stream, the tool executor, the settings store,
  the MCP manager and the token estimator replaced.

## Tests
`tests/test_agent_loop_characterization.py` (17 + 3 H17): text-only answer,
`test_a_nonexistent_tool_is_corrected_once_and_the_turn_then_answers`,
`test_the_correction_budget_of_a_nonexistent_tool_is_two_then_the_turn_moves_on`,
`test_a_context_limit_error_compacts_once_and_redoes_the_round`,
`test_a_second_context_limit_error_in_a_row_ends_the_turn_with_the_reason`,
`test_a_denied_tool_call_is_reported_to_the_model_and_not_retried`,
`test_failing_project_tests_give_exactly_one_fix_round_with_its_budget`,
`test_a_half_done_report_is_rejected_within_its_budget_then_annotated`,
`test_a_stop_request_ends_the_turn_before_the_next_round`,
`test_a_cut_off_reply_is_continued_twice_at_most_with_the_budget_reported`,
`test_an_empty_round_in_a_workspace_turn_is_nudged_within_its_budget`,
`test_an_answer_that_repeats_the_approval_card_is_bounced_twice_at_most`.
`tests/test_extra_round_policy.py::test_the_text_round_decision_order[*]` walks
the whole transition table without a model;
`::test_the_text_round_decision_asks_the_injected_policy_and_nothing_else`;
`::test_every_action_is_reachable_and_named`.

## Evidence
Every scenario asserts the ordered actions (`round:*`, `auto_continue:*[cause]`,
`check:*`, `tool:*`, `cancelled`) and the final state of the turn. The same
scenarios run in `legacy` mode for the extra-round policy and give the same
rounds (`test_the_legacy_mode_keeps_the_same_rounds_without_the_receipts`).

## Remaining limits
- The extraction covers the closing stage of a text-only round and the
  extra-round decisions (H13); the tool-round, compaction and recovery
  branches of the generator are characterized but not yet extracted into pure
  functions. `agent_loop.py` remains a large generator.
- Characterization uses a scripted provider stream, not a live model.
