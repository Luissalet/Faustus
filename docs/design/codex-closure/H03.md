# H03 — if the intent is not persisted, the effect is not sent

**Status: closed with limits** (see the last section).

## Acceptance criterion

An effect that cannot be repeated (a mail, a message, a webhook, a calendar or HTTP
write, a connector write) is sent only after its intent is committed and read back.
If it cannot be committed, nothing is sent. A receiver that commits the action and
then drops the connection leaves the effect `outcome_unknown`; it is reconciled by
identifier and never sent again.

## What was already there

`routes/email_helpers.py` kept a durable record of an outgoing mail intent
(an earlier durable-intent test for mail). Nothing covered the other routes,
and nothing distinguished "failed before sending" from "failed after handing over".

## What was added

- `src/effect_outbox.py`: a write-ahead outbox in its own SQLite file. States
  `prepared -> admitted -> dispatching -> succeeded | failed_before_effect | partial |
  outcome_unknown -> reconciled | cancelled`, with a separate `effect_certainty`
  (`none`, `confirmed`, `partial`, `unknown`). `prepare()` reads the row back and
  raises `IntentNotPersisted` if it is not there; `begin_dispatch()` persists
  `dispatching` before the transport is touched; `dispatch_effect()` /
  `adispatch_effect()` wrap a transport call; `recover_orphans()` turns what a
  previous boot left in `dispatching` into `outcome_unknown` and unsent intents into
  a certain "nothing sent"; `reconcile()` asks a registered finder for the
  identifier and concludes "not landed" only when the finder says its absence is
  authoritative; `resolve_manually()` records a person's finding. Local duplicate
  calls are refused by a partial unique index; an idempotency key counts only where
  the destination is declared to enforce it.
- `src/effect_tools.py` and `src/tool_execution.py`: `describe_call()` decides which
  tool calls are effects; `admit_call()` opens the row before the handler runs; a
  repeated identical call returns the first attempt's state instead of dispatching.
- Routes joined to the outbox: SMTP send (`routes/email_helpers.py`,
  `routes/email_pollers.py`), the mail MCP server (`mcp_servers/email_server.py`,
  which settles the row the tool layer opened through a hidden `_faustus_effect`
  argument), WhatsApp (`src/whatsapp_bridge.py`, `routes/whatsapp_routes.py`),
  integration HTTP writes (`src/integrations.py`), webhooks
  (`src/webhook_manager.py`), CalDAV write-back (`src/caldav_writeback.py`) and
  connector write tools (through the tool layer).
- Setting `agent_effect_outbox` (default on; off restores the plain path).
- Routes and tools to look at it: `GET /api/effects`, `/api/effects/{id}`,
  `.../reconcile`, `.../resolve`; built-in and MCP tool `run_report view=effects`.
  See `docs/api/run_report.md`.

## Remaining limits

- Connector writes (MCP servers other than the built-in ones) are recognised by a
  verb in the tool name; a write with an unusual name is not admitted. They are
  marked `dispatching` before the handler and unknown afterwards, and cannot be
  reconciled automatically (no identifier).
- The SMTP reconciler looks in the default account's Sent folder and treats absence
  as non-authoritative. WhatsApp reconciles by a content fingerprint. Generic
  webhooks have no finder: they need `resolve`.
- `git_push`, `git_open_pr` and the `desktop_*` tools are not in the outbox.
  IMAP flag / move / delete are repeatable and out of scope.
