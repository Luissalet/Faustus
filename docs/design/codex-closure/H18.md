# H18 - No races, with a measured latency advantage

## Acceptance criterion

Parallel tool calls must not race. The dispatcher acquires resource claims (path,
directory, process, external resource) before calls run, under a read/write
compatibility matrix. A preview whose target is unknown gets a conservative write
claim. An external writer (mtime or hash changed between preview and apply) causes a
refusal with a clear error. A benchmark test shows compatible parallel reads finish
faster than sequential and conflicting writes are serialized.

## What was already there

* Per-path mutexes inside the file tools and a parallel group in
  `src/agent_loop.py` that only admitted file edits on distinct paths.
* A review-preview revision check: the apply was refused when the content hash changed
  between preview and apply (`REVIEW_PREVIEW_MISMATCH`).
* No claims, no handling of a same-bytes external touch, no claim for previews whose
  target could not be determined, and nothing shared between concurrent runs.

## What was added

`src/resource_claims.py` (new).

* Resources: `path`, `tree` (a directory and everything under it), `workspace`,
  `process`, `external` (an MCP server or similar), `wildcard`. Matrix: read with read is
  compatible; any write on an overlapping resource conflicts. `overlaps` and
  `conflicts` implement it; a path and a sibling that shares a name prefix do not
  overlap.
* `claims_for_call(tool_type, content, workspace, scope)` turns a tool call into claims:
  reads of named paths, directory reads and searches as trees, writes per named path,
  and a **workspace write when a write's target cannot be determined** (the unknown
  preview case). With scope `files_and_external` an MCP call claims its server and a
  call naming a process id claims the process.
* `ClaimSet` plans a group: `try_add` refuses a claim that conflicts with the group.
* `ClaimBroker` (process-wide via `broker()`): thread-safe, grants a whole claim set
  atomically in FIFO order. No overtaking means a writer is never starved by later
  readers and two runs cannot deadlock by holding half a set each. It works across
  event loops (`call_soon_threadsafe`), supports a wait timeout and cleans up a
  cancelled waiter.
* `run_with_claims(block, workspace, factory, owner)` wraps tool execution. On wait
  timeout it returns a denied result with code `RESOURCE_CLAIM_TIMEOUT` naming the
  blocker; the call is not started.
* External writer detection: `FileFingerprint` (exists, size, mtime_ns, sha256),
  `fingerprint`, `drift`, `external_writer_conflict` and `PreviewBinding`.
  `src/agent_tools/filesystem_tools.py` captures the identity at preview
  (`_identity_conflict`) for `edit_file`, `write_file` and `apply_patch`
  (`prepared_identities`) and checks it after the content-hash check, inside the file
  mutex. Same bytes with a different mtime or size give `EXTERNAL_WRITER_DETECTED`;
  changed bytes still give `REVIEW_PREVIEW_MISMATCH` first.
* `src/agent_loop.py` (small): the prefetch group builds a `ClaimSet` and stops the group
  at a call whose claims conflict; the prefetched, serial and approved execution sites
  go through `run_with_claims`.
* Settings: `agent_resource_claims` (`files` default, `files_and_external`, `off`),
  `agent_resource_claim_wait_s` (120), `agent_external_writer_check` (on).
* MCP: the `harness` built-in server tool `resource_claims` shows the claims of a list of
  calls and the groups that would run together or be serialized.

## Tests

* `tests/test_resource_claims.py`, 36 tests: matrix, overlap, `claims_for_call`
  (including `test_a_write_whose_targets_cannot_be_determined_takes_the_conservative_workspace_claim`),
  broker fairness (`test_a_waiting_writer_is_not_overtaken_by_later_readers`), deadlock
  freedom (`test_a_claim_set_is_granted_all_or_nothing_so_two_runs_cannot_deadlock`),
  timeout (`test_timeout_names_the_blocker_and_releases_the_queue_slot`), cancellation,
  cross-loop wake-up, loop-level tests that drive the real dispatcher
  (`test_loop_read_waits_for_a_write_another_run_holds`,
  `test_loop_call_that_cannot_get_its_claims_is_refused_not_started`), and the
  benchmarks below.
* `tests/test_external_writer_guard.py`, 12 tests, e.g.
  `test_same_bytes_with_a_new_mtime_are_refused_as_an_external_writer`,
  `test_changed_bytes_keep_the_existing_review_conflict`,
  `test_the_check_can_be_turned_off`,
  `test_prepared_patch_is_refused_when_the_target_was_touched_after_preparation`.
* `tests/test_harness_mcp.py::test_resource_claims_groups_reads_together_and_splits_on_a_write`.

## Evidence (measured, `pytest -s tests/test_resource_claims.py -k benchmark`)

| Scenario | Result |
| --- | --- |
| 8 compatible reads, 80 ms each | sequential 0.655 s, claims-parallel 0.081 s (8.1x), peak concurrency 8, no waiting |
| 4 writes to one file | 0.181 s, peak concurrency 1 (serialized), 3 waited |
| 4 writes to four files | 0.040 s, peak concurrency 4 |
| a writer against readers of the same file | never overlaps any of them |

## Remaining limits

* Claims are process-local. Two app processes on one workspace are not coordinated; the
  fingerprint check is what catches an outside writer, and only at apply time.
* Shell commands and calls with unknown effects claim nothing: the claims cannot say what
  a command touches. They are serialized by the existing rules, not by claims.
* `files_and_external` (MCP server and process claims) is opt-in.
* The external-writer check is armed only for reviewed previews and prepared patches. An
  unknown preview has no approval to invalidate, so it stays fail-open apart from the
  conservative workspace claim.
* A call waits at most `agent_resource_claim_wait_s` and is then refused rather than
  started.
