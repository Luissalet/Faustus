# H04 — a timeout after sending does not show as "not executed"

**Status: closed with limits.**

## Acceptance criterion

Every tool result carries an attempt id and an effect certainty. An exception after
dispatch maps to unknown, never to "failed, nothing happened". The UI, the history
and the next turn's recovery keep it.

## What was already there

`src/tool_result.py` normalized results into a typed `ToolResult` with `call_id` and
`attempt_id` (often `unknown`), and a status `outcome_unknown` for some shapes.
The Studio step card could show an "uncertainty" reason.

## What was added

- `src/tool_execution.py` mints one attempt id per execution and binds it
  (`effect_outbox.bind_attempt`) so the outbox, the ledger and the result name the
  same attempt. The result gets `attempt_id`, `effect_id` and `effect_certainty`
  (`none` for reads and local state, `confirmed`, `partial`, `unknown`).
- `src/tool_result.py`, `src/tool_presentation.py`: the certainty and ids travel in
  the typed result and in the presented result that reaches the model and the
  history. An exception after dispatch began is `outcome_unknown`; an exception
  before it is a certain no-effect; cancellation after dispatch keeps the
  uncertainty (`cancelled` with certainty `unknown`).
- `src/agent_runs.py` (`unknown_effects_system_block`) already carried an unknown
  effect into the next turn; the outbox now feeds it with the effect id.
- Studio: `studio/src/adapters/chat.ts`, `studio/src/screens/studio/model.ts` and
  `Transcript.tsx` read `attempt_id`, `effect_id` and `effect_certainty`; a failed
  step with an unknown effect says "This failed, but it may already have taken
  effect. Check the destination before trying again." (es and en strings).

## Evidence

A send whose connection is cut after the body was handed over shows in the step card
as unknown with its attempt id; `GET /api/effects/{id}` shows the state and history.

## Remaining limits

- A generic *failed* result from a tool of an external class gets certainty
  `unknown` but its `status` field is left as the tool reported it (changing it would
  alter every consumer of `status`).
- Tools not registered as effects report certainty `none` only if they are known
  reads or local state; everything else is `unknown` rather than guessed.
