# H08 — execution events do not disappear when the UI compacts

**Status: closed with limits.**

## Acceptance criterion

A causal, append-only ledger per run that can replay the run's state independently of
the UI. An approval granted after a restart resumes the exact pending call, not a
new one.

## What was already there

`src/agent_runs.py` keeps a replay buffer of SSE events per detached run (evicted and
truncated), `src/tool_approvals.py` persists approval cards, and approvals survive a
restart (`tests/test_approvals_survive_restart.py`). Neither recorded which call a
card was made for in a way a replay could check.

## What was added

- `src/exec_ledger.py`: a SQLite ledger (`exec_ledger.sqlite3`) with UPDATE and DELETE
  refused by triggers. One row per causal fact: `run_started`, `run_state`,
  `call_requested`, `approval_requested/granted/denied/expired`, `call_resumed`,
  `attempt_started`, `attempt_result` (with a SHA-256 and a length of the result, not
  its body), `model_call`, `child_result`, `steer_*`. `replay(run_id)` folds the rows
  back into the run's state call by call; `pending_calls()` and `resume_target()`
  answer "what is still waiting, and for which call". A write that fails is counted
  (`summary()["lost_writes"]`) and never blocks or raises. Rows leave only through
  `purge_session()` when the session is deleted.
- `src/tool_execution.py`: a wrapper around the handler writes `call_requested` /
  `call_resumed`, `attempt_started` and `attempt_result` under the original run and
  call id.
- `src/tool_approvals.py` (`call_id` on the card, ledger hooks) and
  `src/agent_loop.py` (one line passing the call id): an approval granted after a
  restart executes the call recorded for that card; the ledger stores
  `args_match` so a changed argument is visible.
- `src/agent_runs.py`: run start and end states; `app.py` startup calls
  `exec_ledger.recover_after_restart()`, which marks runs the dead process left
  running as `interrupted`.
- `GET /api/runs/{session_id}/ledger[?run_id=&events=true]`, `run_report view=ledger`.
- Setting `agent_exec_ledger` (default on).

## Evidence

`GET /api/runs/{session}/ledger?run_id=...` after restarting the server with a card
pending shows the call, the approval and, after approving, `call_resumed` naming the
same call id.

## Remaining limits

- Ledger writes are best-effort (`synchronous=NORMAL`; the outbox uses `FULL`): a
  crash of the machine can lose the last rows, and a failed write is counted, not
  retried. The outbox, not the ledger, is the gate for effects.
- Subprocess runners started by an external runner are not tracked after a restart
  (owned by another part of the system).
- The ledger keeps references to results, not results: it proves which result a call
  produced, it cannot reproduce it.
