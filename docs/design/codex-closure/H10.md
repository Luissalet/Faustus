# H10: portable continuity record and authorizations

## Acceptance criterion

A restart or a model switch does not invent consent. Compaction keeps the most
recent request and its constraints. The record that carries them can move
between installations, and a moved record never grants anything by itself.

## Already there

- Structured approval events on stored messages (`tool_events[].ask_user`)
  are the only source of the chat-session grant (`core/models.py`,
  `_history_grants_chat_session_approval`), exposed to the gate as a
  server-set marker on the last user message.
- Compaction keeps a generated block of objective, constraints, source refs
  and pending card references (`src/context_compactor.py`,
  `CompactionPreserve`), refreshed against the approval store on every prompt
  build (`refresh_compaction_approvals`). Free prose is never promoted.

## Added

- `src/continuity_checkpoint.py` (new):
  - `build_checkpoint`: versioned record (`schema_version`, latest request
    with hash, constraints, decisions, authorizations with proof, evidence
    refs, narrative consent findings, digest), built only from message
    metadata, the compaction block fields and the workspace grants file.
  - `authorization_version`: hash of the effective authorizations only; model,
    prompt and time do not enter it. `save` also keeps a monotonic
    `authorization_seq` that moves only when that version moves.
  - `save` / `latest` / `history`: private SQLite file
    (`continuity_checkpoints.sqlite3` under the data dir), identical content
    does not create a revision, the last 20 revisions are kept.
  - `export_checkpoint` / `import_checkpoint`: digest, schema, owner checks;
    an imported record enters with every authorization demoted to `stale`.
  - `reconcile_authorizations`: re-validates each entry against live evidence
    and returns states `active`, `carried`, `stale`, `revoked`, `expired`,
    `pending`, `denied`. `chat_session_granted` is true only with live
    structured evidence or, behind the setting below, for a verified local
    record of the same chat and owner that was not revoked.
  - `annotate_narrative_consent`: appends a fixed note to a compacted summary
    whose prose looks like consent (English and Spanish patterns). The input
    is not mutated and the note is added once.
  - `observe_run`: the run-level entry point; never raises.
- Settings (`src/settings.py`, `src/agent_settings_schema.py`):
  - `agent_continuity_checkpoint`: `off` / `record` (default) / `annotate`.
  - `agent_continuity_carry_session_grant`: default `false`.
- `src/agent_loop.py` (small): `observe_run` right after the run security
  context is built; a carried grant sets `approval_gate_bypassed`; route
  request state applies the annotation in `annotate` mode; `metrics.continuity`
  (revision, version, counts) rides onto the saved message.
- Read and control surface:
  - HTTP: `GET /api/context/sessions/{id}/continuity`, `.../continuity/export`,
    `POST .../continuity/import` (admin), `POST .../continuity/revoke-carry`
    (admin).
  - MCP (`context_engine` server): `context_continuity` with actions `read`,
    `export`, `verify`, `revoke_carry`.

## Limits

- The only evidence for a chat-session grant is the structured event in the
  stored history. Revoking the carry stops the stored record from keeping the
  grant alive; it cannot remove an event that is still in the history.
- Consent-looking prose detection is a pattern list used to label text, not to
  decide anything. A paraphrase it misses stays unlabelled, and still grants
  nothing.
- No Studio panel yet; the record is readable through the route and the MCP
  tool and the turn metadata.
