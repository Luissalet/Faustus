# WP11 — Recetas ComfyUI más expresivas

Estado: implementado. Flag: `creator_enabled` (ya existente, sin flag nuevo).

## Qué hay

`src/creator/comfy_recipes.py` (nuevo): `ComfyRecipe`, un traductor de **slots
tipados** (`prompt`, `negative`, `seed`, `steps`, `cfg`, `size`,
`reference_image`, `mask`, `controlnet`, `lora`) a los `inputs` declarados de
un `MediaWorkflow` (`src/media_workflows.py`, autoridad sin tocar). No
reimplementa parsing, fingerprint ni review — todo eso sigue siendo de
`media_workflows`. `compile(recipe_id, params)` valida contra un
`ParamSchema` de `src/creator/params.py` (registrados aquí para
`engine="comfyui"`, tasks `image.generate[.lora]/edit/inpaint/controlnet/
upscale`), traduce slot→input y llama a `workflows.render()`: mismo input →
mismo grafo → mismo fingerprint (probado). `compile_batch()` genera N
grafos, un seed por variante. `explain(recipe)`/`describe(recipe)` exponen
modelos, nodos requeridos y `review_status()` en texto legible.

Catálogo de fábrica (7 recetas, cada una con su plantilla nueva en
`config/media_workflows/`, revisada en
`config/media_workflows/reviews/approved_recipes.json` con `fingerprint_version:
2`): `txt2img`, `txt2img-lora`, `img2img`, `inpaint` (IMG04 — máscara y
referencia resueltas a uploads propios del motor, la máscara nunca viaja como
campo de conditioning, solo como input tipado MASK vía `VAEEncodeForInpaint`),
`controlnet-pose`, `controlnet-depth`, `upscale` (IMG09 — el receipt conserva
resolución de origen y el escalador usado; sin tiling, documentado como límite
explícito, no asumido). Todos los grafos usan solo nodos core de ComfyUI.

Recetas de usuario: `create_user_recipe()` acepta un cuerpo con la misma
forma que un archivo de `config/media_workflows/*.json`, lo parsea con
`workflows.parse()` (rechazo inmediato si el shape es malo) y lo guarda
owner-scoped en `DATA_DIR/creator/comfy_recipes.sqlite3` (mismo patrón que
`budget_account.py`: WAL, `BEGIN IMMEDIATE`, conexión cerrada por llamada).
Su id nunca está en `approved_recipes.json`, así que `review_status()` la
reporta `not reviewed`; y como `media_runs.start()` solo carga plantillas
POR ID DESDE DISCO, una receta de usuario no tiene ningún camino a submit —
la cuarentena es estructural, no un gate adicional que se pueda olvidar.

Enganche aditivo en `src/creator/adapters/comfyui.py::plan()`: acepta
`recipe_id + params` (slot-keyed) además de `workflow_id + inputs` crudos,
vía `comfy_recipes.resolve_for_adapter()`; si `op` no es una receta conocida,
el comportamiento legado es idéntico byte a byte (mismo `media_runs.plan()`).

Rutas `routes/creator_recipe_routes.py` (montadas en `app.py`):
`GET /api/creator/recipes`, `GET /api/creator/recipes/{id}` (explain +
slots + review_status + modelos/nodos), `POST /api/creator/recipes/{id}/compile`
(grafo + fingerprint, o `variants` si se pasa `seeds`, nunca envía),
`POST /api/creator/recipes` (receta de usuario, queda `unreviewed`). Owner
siempre de la sesión; "no es tuyo"/"no existe" responden igual (404).

## Migración / rollback

Aditivo puro: 7 archivos JSON nuevos bajo `config/media_workflows/`, 7
entradas nuevas en `approved_recipes.json`, un módulo nuevo, un router
nuevo, una línea en `app.py`, un método `plan()` con firma retrocompatible
(`owner` es keyword-only con default `""`). Rollback: revertir el commit;
nada muta filas existentes ni cambia el fingerprint de una plantilla ya
aprobada.
