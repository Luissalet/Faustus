# WP01 — Regresiones de contratos existentes (QA01)

## Qué hay

Tres correcciones/pruebas sobre autoridades existentes, sin crear ninguna nueva.

**1. `src/media_workflows.py::MediaWorkflow.fingerprint()`** omitía `models`,
`requires_nodes` y `outputs`: dos recetas con el mismo `graph` pero distinto
checkpoint (o `requires_nodes`/`outputs`) producían el mismo fingerprint, así
que aprobar una en `review_status()` aprobaba silenciosamente a la otra.
Arreglado con versión explícita:

- `FINGERPRINT_VERSION = 2` (nuevo default de `.fingerprint()`): añade
  `models`/`requires_nodes`/`outputs` al hash.
- `FINGERPRINT_LEGACY_VERSION = 1`: reproduce byte a byte el cálculo de ocho
  campos previo al fix. `.fingerprint(fingerprint_version=1)`.
- `review_status()` ahora compara cada entrada del registro contra la versión
  que esa entrada declare (`entry.get("fingerprint_version")`, por defecto
  `1` — ninguna entrada existente lo declara). **Ninguna entrada de
  `config/media_workflows/reviews/approved_recipes.json` se tocó ni se
  invalida**: las cuatro plantillas de fábrica siguen `reviewed: True`
  (probado). Una entrada nueva puede fijar `"fingerprint_version": 2` para
  quedar atada a la identidad completa.
- `to_dict()` añade `"fingerprint_version"` (informativo).

**2. `src/media_capabilities.py::_run_version()`** declaraba `installed=True`
en cuanto el subproceso terminaba, sin mirar `returncode`. Un `ffmpeg` que
arranca y sale con código 1 se reportaba como instalado. Arreglado:
`installed` ahora exige `returncode == 0`; el mensaje de detalle nombra el
código de salida. Es un probe en vivo, no dato persistido — no hace falta
versión de esquema.

**3. `src/media_edit_projects.py::export()`** — orden de composición
verificado con fixtures PIL de 8×8: `history` (crop/rotate/flip) se aplica
PRIMERO, en el orden grabado, sobre una copia del original; las capas se
pintan DESPUÉS, en el orden en que se añadieron, sobre el lienzo ya
transformado. Las coordenadas `x`/`y` de una capa son siempre relativas al
lienzo POST-transformación. No se detectó ningún bug confirmado en ese orden
— por tanto **no se cambió**. Se fijó como contrato con
`OPERATION_SEMANTICS_VERSION = 1`, grabado en `create()` y devuelto en
`export()`.

## Rutas / flags

Ninguna ruta ni flag nuevos. `creator_enabled` no aplica a este lote (no toca
`src/creator/`).

## Migración / rollback

- Fingerprint: aditivo y retrocompatible por diseño (ver arriba). Rollback =
  revertir el commit; nada en disco cambia de formato.
- ffmpeg: comportamiento en vivo, sin estado persistido que migrar. Rollback
  = revertir el commit.
- Editor de imagen: `operation_semantics_version` es un campo nuevo en
  registros NUEVOS; un proyecto ya guardado sin el campo se sigue
  comportando igual (nunca se leyó ese campo para decidir el orden). Rollback
  = revertir el commit; los proyectos ya exportados no se ven afectados
  porque el orden de composición no cambió.
