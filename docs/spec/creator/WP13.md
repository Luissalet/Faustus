# WP13 — Timeline y relojes

Estado: implementado y probado (29 tests backend en `test_creator_wp13.py` + 7 en
`test_creator_wp13_routes.py`, `tsc --noEmit`/`vite build` en verde, check
`creator-timeline.check.mjs` en verde). Depende de WP12/WP05 (fusionados en HEAD).

## Qué hay

- **`src/creator/timeline/clocks.py`** — `convert_ticks` entre dos `Rational` (WP12)
  exacto vía `fractions.Fraction`, con `rounding` explícito (`floor`/`ceil`/`nearest`),
  nunca implícito. `MasterClock` envuelve el `clock` del documento. `PtsIndex` indexa un
  origen VFR por una tabla explícita de PTS por frame (estrictamente creciente) — el
  "proxy documentado" del criterio de cierre, nunca un fps medio; `frame_at_tick`
  (`floor`/`nearest`), `to_cfr` resamplea a una tasa constante con política explícita.
- **`src/creator/timeline/tracks.py`** — lectura/validación sobre el `content` que
  `timeline_ops.py` (WP12) ya muta: `validate_track`/`validate_all_tracks` (solape SÓLO
  por pista, nunca entre pistas), `cut_points`, `track_span`. Marcadores viven en
  `content.markers` (campo aditivo a nivel de documento, no un `track.kind` nuevo — no se
  tocó el enum de 5 kinds de `documents.py`): `get_markers`/`add_marker`/`validate_markers`.
- **`src/creator/timeline/retiming.py`** — `map_time(RetimingMap, tick)` sobre el
  `RetimingMap` de WP12: interpolación lineal dentro de un segmento, `source_ticks=None`
  (nunca un valor adivinado) para un tick en una zona `mappable=False` o fuera de todo
  segmento levanta `InvalidOperation`. `cut_boundaries`/`unmappable_ranges` para SUB10.
- **`src/creator/timeline/snapping.py`** — `snap`/`snap_candidates`: cortes y marcadores
  SIEMPRE priman sobre la rejilla de frames, luego distancia, luego tick más bajo
  (determinista). Puro, sin E/S.
- **`src/creator/timeline/validate.py`** — `validate(content) -> ValidationReport`:
  informe completo (no sólo el fragmento que toca un op) con un `Finding` por problema,
  `target` explícito (`track_id` o `track_id:clip_id`) para que la UI salte directo.
- **`src/creator/timeline/project_view.py`** — `project_view` (proyección plana y
  ordenada para el Studio) y `to_edl` (CMX3600 mínimo, una pista de vídeo).
- **`src/creator/ops/timeline_ops.py`** (WP12, extendido SOLO aditivo) — 4 ops nuevas:
  `timeline.snap` (mueve un clip al snap más cercano, re-valida solape), `timeline.retime`
  (adjunta `clip.retiming_map`, campo aditivo), `timeline.add_marker`, `timeline.ripple_insert`
  (inserta y desplaza los clips posteriores de la MISMA pista — el inverso de
  `ripple_delete`).
- **`routes/creator_timeline_routes.py`** (nuevo) — `GET .../timeline/{view,validate,edl}`,
  `GET .../revisions/{n}` y `POST .../undo`. Esta última rutas cablea `ops/undo.py::undo_to`
  (WP12), que no tenía ruta HTTP en ningún WP anterior — ver `WP13_wiring.md` para el hueco
  exacto que llena. Montada en `app.py` con una línea `app.include_router(...)`, mismo
  patrón que los demás `routes/creator_*.py`.
- **Studio**: `Timeline.tsx` (toolbar: undo/redo por revisiones vía `POST .../undo`,
  zoom, playhead, teclado J/K/L shuttle + flechas por frame + I/O in/out local) +
  `TimelineTrack.tsx` (SVG, una pista por fila, clips arrastrables con snap-preview
  cliente vía `adapters/creator_timeline.ts::previewSnap`, commit SIEMPRE server-side vía
  `timeline.snap` — nunca aplicado optimista) + `adapters/creator_timeline.ts` (wrappers
  tipados de las 10 ops de timeline + las 5 rutas de lectura nuevas). Tab «Timeline» en
  `CreatorScreen.tsx` (solo añadido, por defecto para documentos `kind==='timeline'`, con
  alternancia a la vista JSON existente).

## Flag y migración

Sin flag propio: usa `creator_enabled` (WP02) — las nuevas rutas comprueban el flag antes
de tocar el store, igual que `creator_routes.py`. Puramente aditivo: ningún op ni campo
existente cambió de significado; `content.markers`/`clip.retiming_map` son campos nuevos
que un documento antiguo simplemente no tiene (tratado como lista vacía / ausente).
Rollback: `git revert` del commit de rutas+ops+Studio; sin él, `apply_command` no reconoce
los 4 tipos de op nuevos y responde `InvalidOperation` (400) como con cualquier tipo
desconocido — ningún dato queda en un estado a medias.

## Qué queda

- `timeline.retime` sólo adjunta el mapa; ningún adaptador (WP10/WP11) lo consulta aún
  para renderizar una rampa de velocidad real — eso es trabajo de integración futura.
- `to_edl` es deliberadamente mínimo (una pista de vídeo, sin disoluciones/wipes); VID09
  (transiciones/keyframes) es un WP separado que puede extenderlo.
- El historial de revisiones para undo/redo en el Studio es de sesión (se reconstruye
  sólo con los cambios hechos desde que se abrió el documento) — cargar el historial
  completo desde `GET .../history` para poblar undo/redo tras recargar la página queda
  pendiente.
- `PtsIndex`/`to_cfr` no están cableados a ningún adaptador real (ffmpeg/ComfyUI); son la
  base para cuando un WP de ingesta necesite indexar un origen VFR real.
