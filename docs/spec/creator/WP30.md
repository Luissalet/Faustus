# WP30 — Recursos físicos y modo conservador (cierre)

Estado: implementado y probado. No integrado en `app.py` (fuera de la
propiedad de ficheros de este lote; ver `WP30_wiring.md`).

## Qué hay

`src/creator/resources.py` (nuevo, sin reinventar ninguna autoridad
existente):

- **Inventario físico** (`device_inventory()`): GPUs deduplicadas por
  identidad física, delegado en `src.memory_budget.physical_budgets()`
  (INF-05) sobre `gpu_topology.snapshot()` + `gpu_shared_memory
  .vram_snapshot()` — dos endpoints de la misma tarjeta ya se pliegan en
  UN `MemoryBudget`, y una tarjeta no identificada ya llega con
  `gpu_key: None`, nunca como capacidad libre inventada. RAM vía
  `system_memory()`, disco vía `shutil.disk_usage(DATA_DIR/creator)`, CPU
  vía `os.cpu_count()`.
- **Modo conservador** (`creator_resource_mode`, default `"serial"`):
  `"serial"` = una carga pesada a la vez por dispositivo
  (`max_concurrent=1`, sin aritmética de bytes). `"measured"` = concurrencia
  solo si la suma de huellas admitidas más la nueva cabe en `free_bytes`
  del dispositivo menos `creator_vram_margin_mb`; sin capacidad medida cae
  a la regla serial — "desconocido nunca es capacidad libre" vale también
  en la puerta, no solo en el inventario.
- **Huellas por operación**: `DATA_DIR/creator/resources.db` (sqlite, WAL,
  `BEGIN IMMEDIATE`, conexión cerrada por llamada — patrón de
  `src/budget_account.py`), clave `(workflow_id, version, engine, shape)`
  donde `shape` (`shape_key()`) recoge width/height/frames/duration/fps
  cuando el workflow los resuelve — nunca seed ni prompt: una medición a
  512px nunca prueba cabida a un shape distinto (MOD09). Sin medición:
  estimación plana conservadora (`DEFAULT_UNMEASURED_VRAM_BYTES` +
  `vram_fit.DEFAULT_RESERVE_BYTES`, reutilizado). `record_measurement()`
  solo ensancha, nunca reduce con una sola muestra. `note_inflight()`/
  `settle_inflight()` capturan un delta REAL (VRAM del pool antes/después
  vía `gpu_shared_memory.vram_snapshot`); un delta negativo o ausente se
  descarta como ruido.
- **La puerta**: `admit(op_footprint, device, *, run_id, priority=
  "background", mode=None) -> Admission{ok, wait_for, reason, lease_id,
  pool_id}`, construida enteramente sobre `resource_admission.define_pool`
  /`acquire`/`release` (no reescritos): un pool `"creator:<device>"` por
  dispositivo, `acquire(timeout=0)` no bloqueante. `release(run_id)` es
  no-op seguro para un run nunca admitido (mismo contrato que
  `resource_admission.release` sobre un lease ya liberado).

`routes/creator_resources_routes.py` (nuevo, NO wireado):
`GET /api/creator/resources` → inventario + admisiones activas + cola de
runs `queued` con motivo `resource_wait:` (leída de `media_runs`, sin
crear una tabla paralela). 404 con el flag apagado, antes de tocar nada.

`src/settings.py`: añadidas `creator_resource_mode` (default `"serial"`) y
`creator_vram_margin_mb` (default `512`) a `DEFAULT_SETTINGS` — únicas
líneas nuevas.

`src/media_runs.py` (tocado SOLO en las llamadas de admisión, ver
CONTRATO.md): en `start()`, justo antes de `engine.submit(...)`, se llama
`_creator_admit()`; si no admite, la fila queda `queued` con
`reason="resource_wait: ..."` y NUNCA se llama a `engine.submit()`. Se
libera (`_creator_finish()`, `settle_inflight`+`release`) en cada
transición terminal: `_poll()` (completed/failed/cancelled), `reconcile_run()`
(`no_correlation`/`never_queued`) y `cancel()`. Un fallo `submit_unknown`
NO libera — el render puede seguir vivo en el engine; se libera cuando
`reconcile_run` lo asiente. El lado de admisión está gateado por
`_creator_enabled()` (lee `creator_enabled`, default `False`); `release`/
`settle` se intentan siempre (no-op si nunca se admitió), para que apagar
el flag a mitad de un run no deje un lease huérfano. Cualquier excepción
interna degrada a "seguir sin admisión" (fail-open), nunca bloquea un
render por un bug de este módulo nuevo.

## Migración / rollback

Aditivo puro: una tabla sqlite nueva bajo `DATA_DIR/creator/resources.db`,
dos claves de setting nuevas, un router nuevo sin montar. Con
`creator_enabled=False` (default), `resource_admission.acquire` no se
llama nunca desde `media_runs.py` — probado con un spy
(`test_flag_off_admission_is_never_called_and_behaviour_is_unchanged`).
Rollback: revertir el commit; nada en `core/database.py` ni en el schema
de `media_runs` cambió.

## Pendientes

- No hay reintento automático de un run `queued` por `resource_wait`; hace
  falta llamar `start()` de nuevo (o una futura pasada de scheduler) al
  liberarse el dispositivo — `media_scheduler.py` no es mío.
- `settle_inflight` mide un delta de VRAM a nivel de POOL, no por tarjeta
  física — ruidoso con actividad LLM concurrente en la misma GPU; límite
  conocido, documentado.
- `admit()`/`release()` corren un `asyncio.run()` por llamada (el llamador
  es código síncrono vía `asyncio.to_thread`); ver `_run_sync` para por
  qué es seguro con `timeout=0`.
