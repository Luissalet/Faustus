## When to Use

The person is running a job search with several postings in different states and wants a reliable record, reusable answers to common questions, and applications that fit each posting. This procedure does not invent experience, does not submit applications on someone's behalf without their say, and does not cover salary negotiation.

## Procedure

1. Read the app's tool list. Start with the stored context: the person's background, roles sought, constraints (location, salary floor, notice period, languages) and the facts that may be quoted. If it is thin, ask for the missing facts and store them as facts, separated from preferences.
2. Record each job with the source address, company, role, location, date found, the closing date if any, and the requirements copied from the posting. Keep the posting text; postings disappear.
3. Compare the posting with the context before applying: which requirements are met with evidence, which partly, which not. Say it plainly. This decides whether to apply and what to emphasise.
4. Tailor the application from true material only. Choose the two or three achievements from the stored context that answer the posting's main requirements, use the posting's vocabulary where the person's experience genuinely matches, and leave out the rest. Check every sentence of the draft against the context; delete what cannot be backed.
5. Store reusable answers (why this field, a difficult situation, strengths, availability) with the context in which they were used. Reuse them as a base, never paste them unchanged into a question that asks something different.
6. Create the application record when the person approves it: date sent, channel, documents sent, contact. Set the status by a fixed vocabulary (planned, sent, interview, offer, rejected, withdrawn) so the list can be filtered.
7. Schedule follow-ups: a reasonable wait after sending, after each interview, and before a stated deadline. Write the follow-up as a short note with one specific question or addition.
8. Review weekly: which postings are stale, which need a follow-up, which sources produce interviews. Adjust the search from that.

## Pitfalls

- Embellishing a requirement match; interviews expose it in minutes.
- Sending the same document to every posting.
- Statuses left unchanged after a rejection email, so the list lies.
- Losing the posting text after it is taken down.
- Follow-ups that only ask for news and add nothing.
- Storing sensitive personal data beyond what applications need.

## Verification

- Each job has its posting text, address and status.
- Every claim in a tailored application is traceable to the stored context.
- Applications sent have a date, channel and document list.
- Each open application has a next action with a date.
