## When to Use

A person gives you a brief (audience, goal, length, tone) and one or more source documents, and wants a deck they can still edit. This procedure covers the path from brief to exported file. It does not cover designing a brand theme from scratch, laying out a poster, or writing a long report that happens to be shown on slides.

## Procedure

1. Read the app's tool list, then write down the brief in four lines: who will watch, what they should decide or remember, how long the talk is, and the tone. If any of the four is missing, ask once before creating anything.
2. Create the deck and add the sources. Add only documents the person named; a deck built from extra files carries claims nobody approved. Check that each source was read (it reports text, not just a filename).
3. Generate the outline before any slide. Read it as a story: each slide title should be a full conclusion ("Churn fell because onboarding got shorter"), not a topic ("Churn"). Reorder, merge or delete entries until the titles read in sequence as the argument. Show the outline to the person when the deck is more than a handful of slides.
4. Generate the slides. Each slide carries one message, a few lines of body, and speaker notes that say what to say aloud and where the number comes from. If a slide needs two messages, split it.
5. Review slide by slide, not in bulk. For each slide check: the title states the point, the body supports only that point, every figure matches the source (use the app's number check against the sources), and the notes can be spoken in the time you have. Approve a slide only after this; regenerate or edit the ones that fail, and revert when a regeneration is worse.
6. Handle images deliberately. Prefer a chart or a figure from the sources over decoration. Record where each picture came from; a generated picture of a real product or person is a claim.
7. Choose the theme last, so content decisions are not distorted by layout. Look at the longest title and the densest table on the chosen theme.
8. Export in the format the person will use (editable file for further work, PDF for sending). Open the export or its preview and check that charts and text are still native and not flattened to images.

## Pitfalls

- Generating all slides from a vague brief and then polishing: the structure is wrong and polish hides it.
- Topic titles ("Results", "Next steps") that make the audience read the body to learn the point.
- Numbers rounded or restated differently on different slides, or taken from memory instead of the source.
- Speaker notes that repeat the slide text; they should carry what the slide does not.
- Approving slides without looking at them after an automatic regeneration changed them.
- Too many slides for the time: roughly one message per minute is a ceiling, not a target.

## Verification

- The outline titles, read alone, tell the whole argument in order.
- Every number on every slide was matched against a named source and the check reported no mismatch, or the mismatch is explained in the notes.
- Each slide is approved individually and has speaker notes.
- The exported file opens, has the expected slide count, and its path is given to the person together with the formats produced.
