## When to Use

The person keeps a collection of video games and wants a reliable record of what they own, what they are playing, how long they have played and what to do with the pile of unplayed ones. This procedure covers entering and maintaining the library and reading its statistics. It does not review games for quality and does not buy anything.

## Procedure

1. Read the app's tool list. Check how the library is stored and whether an online catalogue key is configured; without one, entries are written by hand and covers or metadata will be missing, which is fine but should be known.
2. Import the store library if one exists, and check the result: the count compared with the store's own count, titles that came in twice under different editions, demos and tools counted as games. Merge duplicates and remove non-games.
3. Give every game a status from a fixed list (backlog, playing, finished, dropped, shelved) and use it consistently. Platform, ownership and a rating are optional, but a rating without a date hides that tastes change.
4. Record sessions at the moment they happen if possible: date, minutes, optional note. Estimate only when the person says it is an estimate, and mark it. Total playtime is the sum of sessions, so a wrongly entered session is worth correcting rather than adding another to compensate.
5. Handle DLC and editions explicitly: attach DLC to its base game, record whether it was bought, and mark finished only for what has actually been completed, so a finished base game with an unplayed expansion remains visible.
6. Make backlog decisions with the person using facts: how long a game takes, how long it has sat unplayed, how recently it was wanted, and what the person feels like playing. Move games to dropped or shelved with a short reason; "dropped" is a decision, not a failure, and clears the list.
7. Read statistics with care: hours by month, by game and by genre, most played, longest unplayed, completion rate. Check that the period covered by session data is the period you describe, since an import of totals without sessions has no history. Report what the data cannot answer.
8. Summarise: changes made, the current play list, and two or three suggested next games with the reasons.

## Pitfalls

- Duplicate entries from several editions.
- Mixing hours imported from a store with sessions logged here and counting them twice.
- Marking a game finished when only the main story is done and the person considers the rest unfinished.
- Statistics over a period that has data for only part of it.
- A backlog sorted by nothing; decide an order or a rule.
- Treating a catalogue match as certain when titles are alike.

## Verification

- Library count after import matches the store's count, minus removed non-games.
- Every game has exactly one status.
- Playtime totals equal the sum of imported hours plus logged sessions, with no double counting.
- Statistics say what period they cover.
- Each dropped or shelved game has a reason.
