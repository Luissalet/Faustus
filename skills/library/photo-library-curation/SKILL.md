## When to Use

The person wants to find a photo ("the one with the red kayak, summer, somewhere coastal"), group photos into albums, or reduce clutter such as duplicates and near-identical bursts. This procedure covers searching, proposing and presenting selections. It does not cover editing images, and it never removes or moves originals on its own initiative.

## Procedure

1. Read the app's tool list and check which folders are indexed and how fresh the index is. A search over a stale index misses recent photos; if the folder is not indexed, say so and index it before searching.
2. Turn the request into three kinds of clue: what is in the picture (objects, scene), where (place names, coordinates from the metadata) and when (a date range). Use the structured filters for place and time and the content search for the rest; combining them narrows far better than a long description.
3. Look at the results as contact sheets, not as a list of filenames. Judge by eye which results match, then refine: add a second query for a different aspect, exclude a wrong cluster, or search for pictures similar to a good hit.
4. When proposing an album, define the rule first (for example "trip to the coast, 12-19 August, all photos with location inside this area") and show the count and a contact sheet. Offer borderline photos separately so the person decides.
5. For clean-up, work in groups: exact duplicates, near duplicates, bursts, screenshots, blurry shots. For each group keep one candidate by a stated rule (largest, sharpest, earliest) and show the group beside the candidate to keep.
6. Present the selection before any action: the count, a sample, the rule, and what would stay. Ask for explicit confirmation for each group. Photos with people, family events or no copy elsewhere deserve the most caution.
7. Carry out only what was confirmed, using the app's own tools, and report what changed with a way to find it again. If a deletion is requested, state that originals are not modified by the app and tell the person the exact list of files to remove themselves.
8. Summarise: albums made, groups reviewed, what was left untouched.

## Pitfalls

- Trusting a place from the metadata when the clock or GPS was wrong; confirm with the image.
- Treating similar photos as duplicates when they are different moments of an event.
- Describing a photo from a filename or one search score instead of looking at it.
- Proposing an album with hundreds of unseen photos.
- Missing photos from a camera that records no location by assuming every photo has coordinates.
- Acting on the whole result set after the person approved only a sample.

## Verification

- Every album has a stated rule, a count and a contact sheet that was shown.
- No file was altered, moved or deleted without a confirmation tied to that exact selection.
- Duplicate groups show which photo is kept and why.
- The report lists what the index did not cover (folders not indexed, photos without metadata).
